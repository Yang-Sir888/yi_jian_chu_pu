# 国韵谱音项目说明

国韵谱音是面向民族音乐资料整理、教学和专家核校的旋律采谱工作台：上传独唱或单件乐器录音，生成待校订简谱初稿，对照原音修改，保存重开并导出 SVG、MusicXML、MIDI 或核验 JSON。

## 当前架构

| 部分 | 实现与职责 |
| --- | --- |
| 前端 | React + TypeScript，浏览器 Worker 运行 Basic Pitch；YIN 为主动选择的备用算法，CREPE 为实验性片段复核 |
| 本地服务 | Express + PGlite 持久数据库；也可通过 DATABASE_URL 使用独立 PostgreSQL |
| 云端服务 | cloud/worker.mjs 兼容 API；D1 保存账号、会话、作品与加密模型配置，私有 R2 保存录音 |
| 百炼助手 | 服务端解析明确的文字记谱要求，执行调号换算、拍号重排、速度设置；不听原音、不修改旋律 |
| 发布 | GitHub 保存源码；Sites 托管前后端运行服务。仓库地址不是专家登录入口 |

完整的安装、云端绑定、环境秘密和运维命令以根目录 [DEPLOY.md](../DEPLOY.md) 为准；项目入口和演示顺序见 [README.md](../README.md)。旧沙箱文档不适用于当前交付。

## 共享密钥和账号

管理员在“账号与模型管理”配置一次百炼 OpenAI 兼容 Base URL、模型名和完整 API Key，专家使用服务端共享配置，无须逐人填 Key。脱敏截图不能用于实际调用。密钥不能写入前端、公开仓库或公开文档。

云端用 MODEL_VAULT_KEY（32 字节随机值的 base64 编码）进行 AES-GCM 加密；本地服务使用受保护的服务端主密钥文件。数据库与主密钥须同时保留，丢失主密钥后必须重填百炼 Key。账号、录音和作品由服务端按所有者隔离；多人共用同一专家账号会共享该账号的数据。

云端默认管理员 admin 首次登录改密；预置评审账号 expert01 可直接体验。管理员另外创建或重置的专家账号首次登录须改密。本地初始化行为以当前 DEPLOY.md 为准。密码不在源码中提供，实际交付记录由所有者保管。

## 数据与能力边界

录音在浏览器内识别，用户点击保存才上传到本平台私有存储。百炼调用仅发送记谱元数据和文字要求。首次访问、登录、保存、重开和百炼调用依赖网络及在线服务，不能宣传“全平台离线”。

识别适合清晰、短时、单旋律录音。Basic Pitch 官方说明更适合单件乐器；当前重叠候选取一个的启发式不是伴奏分离算法。CREPE 片段一致不能保证全曲正确。调号、拍号、速度需专家确认，模型响应值或疑点比例不是经过校准的准确率。整数半音记谱不能完整表达微分音、滑音和民族音乐装饰音。[Basic Pitch](https://github.com/spotify/basic-pitch)、[CREPE](https://github.com/marl/crepe/blob/master/README.md)

换调号保持绝对音高，不等同于真正移调。当前系统不鉴定曲种、民族、地区或文化来源。合成校验音和示例谱已经分别标记，不能冒充真实采录实验。

## 已有软件验证与限制

当前测试文件包括后端 14 组（音乐核心 10、服务端 4）、云端 Worker 5 组、前端导出 5 组。运行方式：

```sh
npm test
npm --prefix frontend test
npm run build
```

云端集成测试使用 Node SQLite 实现 D1 接口替身，并模拟私有 R2；覆盖账号、CSRF、权限隔离、并发版本冲突、共享 Key 加密、模型配额和对象回收。它不能替代真实部署环境中的端到端验证。构建、格式、安全测试通过也不等于真实音乐识别准确率达标。Docker 和真实百炼调用是否实测，应以本次交付记录为准。
