# 国韵谱音 · 面向民族音乐传承的智能简谱识别与生成平台

从录音到简谱的完整工作流：**浏览器内识别 → 专家逐音校订 → 原音对照试听 → 保存重开 → 导出 SVG**。
面向清唱与单件乐器录音，识别结果始终作为校订起点，最终判断保留在专家手上。

## 2. 技术要点

| 关注点 | 做法 |
|---|---|
| 识别 | Basic Pitch 在 **浏览器内** 推理，音频不上传第三方；CREPE 为可选复核，只标疑点 |
| 数据隔离 | 服务端按 `owner_id` 强制过滤，会话身份来自 HttpOnly Cookie，前端无法伪造 |
| 音频存储 | 存为数据库 `bytea`，无公共桶、无直链；仅经所有者校验的 `/api/works/:id/audio` 流式返回 |
| 并发安全 | 作品带 `version`，保存走乐观锁，冲突返回 409 并提示先导出当前谱面 |
| 口令 | scrypt 加盐哈希；会话令牌 SHA-256 后入库；首次登录强制改密 |
| 请求防护 | `helmet` CSP、CSRF 头校验、Origin 校验、分接口限流、上传体积与音频格式校验 |
| 模型密钥 | 只存服务端 `app_settings` 表，接口只回 `keySet: 布尔值`，从不回显明文 |
| 模型调用 | 地址白名单（仅 `*.maas.aliyuncs.com` / `dashscope*.aliyuncs.com` 且以 `/compatible-mode/v1` 结尾），工具仅 3 个且最多 3 步 |

## 3. 快速开始（本地 / 自建）

前置：Node.js 22+、pnpm、PostgreSQL 14+。

```bash
# 1. 后端
cd backend
pnpm install
cp .env.example .env          # 填写 APP_ORIGIN 与 DATABASE_URL
export DATABASE_URL='postgres://USER:PASSWORD@localhost:5432/lupu'
node scripts/setup.mjs        # 建表 + 生成管理员随机密码
                              # 密码写入 .lingpu/setup-credentials.json（0600），不在控制台打印
node src/index.mjs            # http://localhost:3000

# 2. 前端（另开终端）
cd frontend
pnpm install
cp .env.example .env
pnpm dev                      # http://localhost:5173，/api 自动代理到 3000
```

生产构建：`cd frontend && pnpm build`，产物在 `frontend/dist`，由后端静态托管（含 SPA 回退），单端口即可对外。

## 4. 数据库脚本执行顺序

平台迁移通道**每次只接受一条语句**，请逐条执行：

1. `backend/sql/01-schema.sql` — 建表与索引（`IF NOT EXISTS`，可重复执行）
2. `backend/sql/02-rpc.sql` — 9 个 `lingpu_*` 存储函数（含授权语句，整段执行）
3. `backend/sql/03-rls-and-grants.sql` — 逐条执行，开启 RLS 并确认权限

`02-rpc.sql` 中的函数均为 `SECURITY DEFINER`，且仅 `GRANT EXECUTE ... TO service_role`，
浏览器侧角色（`anon` / `authenticated`）无执行权限。这样即使直连数据库也无法越权。

## 5. 双模式数据访问

同一份仓储代码适配两种环境，启动时自动选择：

| 模式 | 触发条件 | 实现 |
|---|---|---|
| **云通道** | 存在 `.env.tcb` 且含 `CLOUDBASE_ENV_ID`（或 `TCB_PG_PROXY=1`） | 经平台代理 `pg/query` 单语句通道；需要事务的写操作调用 `lingpu_*` 函数，在数据库内完成事务与乐观锁 |
| **本地连接池** | 设置了 `DATABASE_URL`（或 `TCB_PG_PROXY=0`） | 标准 `pg` 连接池 + 真实事务 |

云通道遇到瞬时断连会**自动重试读操作**（最多 3 次）；写操作仅在确认未拿到响应时重试，避免重复写入。

## 9. 百炼（智能整理）状态

- **默认未接通**：界面明确显示「百炼未接通」，识别、编辑、试听、保存、导出全部可用。
- 接通方式：管理员登录 →「账号与模型管理」→ 填 Base URL（须为 `https://*.maas.aliyuncs.com/.../compatible-mode/v1`）、模型名、API Key。
- 密钥安全：仅存服务端数据库；前端只拿到 `keySet` 布尔值；带 `*` 的打码值会被服务端拒绝。
- 费用尚未取得账单证据，不能声称零费用。模型免费额度到期或耗尽后可能转为按量计费，主机、数据库、持久盘及带宽也可能收费。[百炼费用管理](https://help.aliyun.com/zh/model-studio/bill-query-and-cost-management)

## 10. 当前能力与文档适用范围

本文件前文保留原交付包的历史架构说明；其中固定测试项数、云环境路径、SQL 文件清单及发布方式须以当前源码、实际测试报告和根目录部署说明为准，不作为已验证的交付承诺。

平台定位是“清唱或单件乐器录音生成可校订简谱草稿”。Basic Pitch 官方也指出更适合单件乐器；当前重叠音候选取一个的规则不是伴奏分离算法。CREPE 为单音高跟踪器，只在部分片段做实验复核。两者的响应值都不是本项目经过校准的识别正确概率。整数半音记谱不能完整表达微分音、滑音和民族音乐装饰音。[Basic Pitch](https://github.com/spotify/basic-pitch)、[CREPE](https://github.com/marl/crepe/blob/master/README.md)

本地识别不等于整个平台完全离线。登录、保存、重开、管理和百炼调用需要可达的服务端；百炼整理需要联网。调用百炼时只发送记谱元数据和文字要求，不发送原始录音；用户主动保存时，录音会上传到本平台私有存储。文本助手不能听原音，也不能据此鉴定曲种、民族和地区。

管理员只配置一次完整百炼密钥，全体专家免填密钥；截图中的脱敏值无法调用。密钥必须留在服务端并持久化，备份应覆盖数据库和加密主密钥。当前实现与参赛缺口详见《评审改进与证据.md》。
