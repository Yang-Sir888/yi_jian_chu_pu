# 评审改进与证据

核验日期：2026 年 11 月 10 日，北京时间。以下区分规范、建议和待采集证据，不虚构准确率、用户数或专家背书。

## 前提核查

- **日期有更新。** 用户提供的《作品要求.pdf》落款 2026-09-28，原截止 10 月 20 日。核验时，大赛官方首页显示校赛报名及作品上传截止为 **2026 年 11 月 10 日 24:00**；校赛 11/11-11/20、区域赛 11/21-12/11、总决赛 12/25-12/27。官网列有 10 月 13 日调整通知。最终仍应核对报名平台、参赛阶段和所在赛区最新通知。[比赛官网](https://www.ai-race.com.cn/)
- 赛事名称须对应“第二届全国人工智能应用创新大赛”，不要混用名称接近的“中国人工智能应用创新大赛”或“兴智杯”。
- “一键出谱”应解释为“一键生成可校订草稿”。当前不保证复杂混音抽取主旋律，不生成完整总谱，不自动鉴定文化来源。
- 百炼处理的是文字记谱要求；音高识别由专用模型完成。换用更大的文本模型不能直接提高音符识别准确率。
- GitHub 托管代码，GitHub Pages 为静态托管；共享密钥、会话和保存功能需要后端。仓库地址不能替代专家实际使用网址。[GitHub Pages 官方说明](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages)
- PDF 要求作品内不出现学校、学生、导师信息，但文件命名又要求学校和队长姓名。应区分正文与文件名并核对平台要求；公开仓库提交记录、页面昵称、文件名和导出元数据也可能泄露身份。

## 建议定位

建议聚焦“面向民族音乐教学与采录整理的可核校简谱生成助手”。这是教育领域定位建议，不代表用户已选择该赛道；已参赛时保持原题目和主题。

建议论证两个创新点：一是保留原音时间锚点、疑点和专家修改的证据链；二是将自然语言限定为可验证的调号换算、拍号重排、速度设置。价值应通过减少校订时间与错误来证明，不能只靠界面或“民族音乐+AI”的标签。

| 评审可能追问 | 可验证的回应 |
| --- | --- |
| 只是给开源模型套界面？ | 展示识别、疑点定位、原音对照、专家校订、标准导出的闭环，并与基线实测比较 |
| 为什么需要大模型？ | 自然语言解析负责记谱要求；专用音频模型负责音符，两者职责不同 |
| 对民族音乐有什么适配？ | 展示自由节奏与装饰音复核，承认微分音和滑音局限，不凭曲风推断民族归属 |
| 响应值 0.8 是不是 80% 正确？ | 不是，未校准；准确率须对专家参考谱评测 |
| 民歌录音能随便用吗？ | 曲调、编配、表演、录音及采录授权需要分别核查 |
| 专家免填 API 是否没成本？ | 管理员承担共享调用费用，主机、存储、带宽亦可能计费 |

## 技术来源与边界

- [Basic Pitch 官方仓库](https://github.com/spotify/basic-pitch)支持多音高，同时说明更适合单件乐器。当前代码对重叠候选取模型响应最高的一条并提示疑点，不能称为已验证的主旋律分离。
- [Basic Pitch TypeScript](https://github.com/spotify/basic-pitch-ts)用于浏览器推理，需记录实际版本与运行设备。
- [CREPE 官方说明](https://github.com/marl/crepe/blob/master/README.md)是单音高跟踪；当前只对片段抽样，不等于全曲正确性检查。
- 当前 `recognize.worker.ts` 的调号、拍号为待确认值，速度为估计值；整数半音不能完整保留微分音与滑音。
- 当前 `agent.mjs` 只收到记谱元数据和文字；不听录音，不能鉴定曲种、民族或地区，也不修正旋律音符。

## 评测方案：待执行

先做小规模探索，例如至少 20 段授权录音并按类型分层，再扩展到更多人、设备、曲目和乐器。此数量只是启动建议，不足以支撑普遍适用的结论。

| 变量 | 建议方法 |
| --- | --- |
| 数据 | 清唱、笛箫、拉弦、弹拨；另列噪声、混响、自由节奏、装饰音、混音失败例 |
| 来源 | 自录并获演奏者同意；开放数据逐项核对许可；专家授权留存范围 |
| 参考谱 | 两名有记谱经验者独立标注音高与起止时间，协商分歧，保留版本 |
| 基线 | Basic Pitch 对 YIN；人工从零记谱对平台辅助校订 |
| 音符指标 | 预先固定音高与起点容差，一对一匹配计算 Precision/Recall/F1；例如 50 cents、50 ms 是可讨论的容差，不是实测结论 |
| 时值 | 分别报告起点、终点误差的分布，合并延音再比较，避免重排导致的音符数误读 |
| 流程 | 首次草稿耗时、最终校订耗时、修改次数、失败率与导出成功率 |
| 公平性 | 固定参数、同一录音与参考谱，控制熟练度和顺序，避免挑样本 |
| 报告 | 分层样本数、区间或分位数、失败原因、版本与测试日期；失败样本不得删除 |

建议记录字段：样本编号、来源许可、演奏同意、类别、时长、设备、浏览器、模型版本、算法参数、参考谱版本、容差、P/R/F1、起止误差、识别耗时、校订耗时、修改次数、失败原因。

软件测试通过只说明相应功能路径工作，不能推出真实音乐识别准确率。合成音只用于验证可复现流程，不能独自支撑民族音乐优越性结论。

## 三个提示词与应验证的条件

1. “保持实际音高，把记谱调号换算为 G 调。”预期调号 G，所有非休止音绝对 MIDI 音高不变。换调号不是移调。
2. “按 3/4 拍重排小节，不要增加或删除旋律。”预期拍号 3/4、总时值不变；可能拆音并增加延音线，应比较合并延音后的序列。
3. “速度设置为每分钟 88 拍，保持调号和音高不变。”预期速度 88，调号、音高序列和总拍数不变；合成试听秒数可变化，原音不会变速。

再演示一个不支持的文化归属鉴定请求，说明缺乏证据时不能自动得出结论。保留实际请求与输出，不能把文字设想当作成功调用记录。

## 部署和成本

管理员配置一次密钥，专家无需自带密钥；Key 必须留在服务端且不可进入公开仓库。加密主密钥、作品数据库和录音都须持久保存并备份。截图为脱敏值，不能调用。

百炼地域、业务空间、Key 和可用模型须匹配，推荐复制控制台专属 OpenAI 兼容地址；路径以 `/compatible-mode/v1` 结尾。[百炼接口](https://help.aliyun.com/zh/model-studio/regions)

免费额度可能到期或耗尽后转为按量计费。应用限流不等于账单上限；控制台应核查用完即停和费用告警，不得无账单就宣传“未产生付费项”。[百炼费用管理](https://help.aliyun.com/zh/model-studio/bill-query-and-cost-management)

可选 Render 支持仓库 Dockerfile；持久盘只支持付费服务，免费 Web 无法挂盘，15 分钟无流量休眠，唤醒约 1 分钟；免费 Postgres 30 天到期。本地嵌入式数据库必须置于持久卷，不适合放在免费临时文件系统。带盘单实例不等于高可用部署。[Docker](https://render.com/docs/docker)、[持久盘](https://render.com/docs/disks)、[免费限制](https://render.com/docs/free)

最终部署如使用其他托管平台，应单独核查其数据库、对象存储、调用次数、CPU 和出站流量配额，不能把已存在免费层推断为永久免费。

预算表至少包括：运行实例、数据库/持久盘、对象存储、出站带宽、API 输入输出 Token、备份、域名、人工校订时间。没有账单时填“待验证”，不能填零。

专家使用普通账号，管理员单独保管。多人共用账号应先完成初始改密，避免评委相互改密。交付前验证公网 HTTPS 的上传、识别、保存、重开、原音权限、导出和账号隔离；通过赛事私有渠道提交账号密码。

背景与用户；需求及可测目标；数据来源授权；专家参考标注；预处理数据流；方法选择；系统架构；音谱校订；可控助手；创新及对照；评测设计；分层实测结果；校订用时实测；失败例；风险成本；三个提示词；演示及链接；局限与参考。没有实测的数据明确标“待验证”。

6 分钟录屏建议按问题 40 秒、方法 60 秒、真实操作 150 秒、结果与失败例 70 秒、局限成本 40 秒分配。本文是材料建议，尚未创建 PPT 或视频。
